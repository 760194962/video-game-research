# gamedata 格式

所有数值都是大端序。偏移是相对 `gamedata` 文件开头。
标注"推测"的条目只看过数据、没有在游戏里验证过含义。

## 1. 存档包与校验

| 项目 | 内容 |
|---|---|
| 存档包 | STFS `CON `，4,837,376 字节；头大小 0x971A，数据区从 0xA000 开始，块大小 4 KiB |
| gamedata | 4,718,624 字节，1153 块，从数据块 1 开始连续存放 |
| 块映射 | 数据块 n → 实际块 r = n+2（n<170），否则 176 + 172×(n/170−1) + n%170；文件偏移 = 0xA000 + r×0x1000 |
| 校验 | 文件前 2 字节 = CRC-16/CCITT-FALSE（多项式 0x1021，初值 0xFFFF），计算范围 0x10 到文件末尾。不对就会显示"ゲームデータが壊れています" |
| 真机写回 | 用 `tools/stfs_gamedata.py inject` 原位写回，再在 Horizon 里做 "Save, Rehash and Resign"。不要用 Horizon 的替换文件功能，它会重新分配，存档包会变成约 9 MB |

## 2. 记录结构

存档由带标签的记录组成：8 字节 ASCII 标签 + u32 版本号 + u32 0，后面是数据，按 16 字节对齐。
版本号来自 xex 里的注册调用，例如 `UNIT    ` v4、`UNIT TAG` v8、`PEVA TAG` v2、`ACDT TAG` v2、`IDOL TAG` v1。

## 3. 偏移表

| 偏移 | 标签 / 内容 | 说明 |
|---|---|---|
| 0x10 | `SYSTEM  ` | |
| 0x20 | `WORLD   `，数据 0x30–0x5F | 若干累计值，玩一周就会变 |
| 0x70 | `PROD TAG` | 0x80：制作人名，UTF-16BE，最多 8 字（16 字节）。真机默认存档里是"アイマス" |
| 0x90 | `PEVA TAG`，数据 0xA0 起 24×i32 | 制作人层的计数（见下表） |
| 0x100 | `MAILDATA` | 邮件 |
| 0xB450 | `PROD TAG` + `UNIT TAG` 等 | 当前 Unit 的工作副本；0xB460 是制作人名的第二份 |
| 0xCE50 | u32 | 配饰+衣装记录条数，必须和后面实际记录数一致，否则判坏档 |
| 0xCE60 | `ACDT TAG` × N | 每条 0x50 字节，容量 246 条（到 0x11B40 为止）。见 `accessories.md` |
| 0x11B40 | u32 | 已获得奖杯数 |
| 0x11B50 | `PTRP TAG` × 已获得数 | 每条 0x20 字节，按获得顺序排列，记录 +0x10 = 奖杯 ID（见 `achievements.md`）；其余为全 0 |
| 0x11C90 | i32 | **制作人等级**（制作人 `+0x48`），0~9，9 = 真アイドルマスター（升降表见 `achievements.md`） |
| 0x11C9C | i32 | 已完成的 Unit 数（制作人 `+0x88`，结局时 +1） |
| 0x11CA0 | i32 | 粉丝数（显示用汇总） |
| 0x11F90 | 10 × i32 | **各偶像的结局次数**（制作人 `+0x60`），下标 = 偶像 ID − 1，亜美/真美共用下标 8，美希是 9；10 个都 > 0 = 10アイドル |
| 0x11FC0 | Unit 槽 × 10 | 每槽 0xB10 字节，见第 5 节 |
| 0x18940 | `SCRIPT  ` | |
| 0x18E60 | `CREL TAG`，0x18E70 | 推测：已完成的 Unit 数（Producer 页"プロデュース数"） |
| 0x18E80 | `PHOTO   ` + 5 × `PHOTOTAG` | 每张约 0xB4060 字节 |
| 0x39D070 / 0x39D090 / 0x39D0B0 | `OP GAME` / `OP SOUND` / `OP DISP` | 设置 |
| 0x39D0D0 | u32 | **Unit 选择界面列出的 Unit 数**。游戏只列出前 N 个槽；往空槽里加 Unit 时必须同时改这个数 |

### 制作人 PEVA（0xA0 起，i32 下标）

| 下标 | 含义 | 可信度 |
|---|---|---|
| 0 | 试镜次数 | 已确认 |
| 1 | 试镜合格次数（胜率 = [1]/[0]） | 已确认 |
| 11 + 12 | C100 的判定值（两项之和 ≥ 100） | 反编译（`achievements.md`） |
| 15 + 16 | L100 的判定值（两项之和 ≥ 100） | 反编译 |
| 19 | 4シーズン 位掩码，低 8 位全满即达成（偶数位 = 季节祭典试镜合格，奇数位 = 季节祭典营业） | 反编译 |
| 20 | M100 的判定值（累计**获得**的回忆数，≥ 100；用掉不减） | 反编译（`0x8222EF30`）。以前记成"累计周数，玩一周 +1"，与反编译不符；一份二周目存档里这里是 37 |
| 21 | 用过的曲目位掩码，低 16 位全满 = 16ソング；引退时按该 Unit 的曲目记录写入 | 反编译 |
| 7 | 课程次数 | 推测 |
| 13 | 推测：担当过的偶像数 | 推测 |

下标与 PEVA 对象偏移的对应见 [week-cycle.md](week-cycle.md) 第 3 节（下标 19 → `+0x60`，20 → `+0x58`，21 → `+0x64`）。以前"把 6、8、9、10、11 设成 99 能触发 A100/C100/L100/M100"的记录，和反编译出的下标不完全一致，当时可能同时改了别的下标。

## 5. Unit 槽（0x11FC0 + k×0xB10）

| 槽内偏移 | 内容 |
|---|---|
| +0x00 | `UNIT    ` v4 |
| +0x10 | `UNIT TAG`，+0x20 = 偶像人数 |
| +0x30 起 | `IDOL TAG` × 人数，每条数据的第 1 个字 = 偶像 ID；后面跟 `ACDT TAG`（装备中的配饰） |
| +0x350 | 状态结构：+0x350 空槽为 −1、使用中为偶像人数；+0x358 = 粉丝数 |
| +0x390 | Unit 名，UTF-16BE，16 字节，默认"ナムコエンジェル" |
| +0x44C | 最近 5 场试镜战绩，5×3 个 i32（名次−1, ?, 合格标志），新的在前，空位 (−1,−1,0) |
| +0x490 | `REPO TAG` |
| +0x4B0 | `PEVA TAG`，数据 +0x4C0 起 24×i32（Unit 层计数，[0]/[1] 同样是试镜/合格） |
| +0x520 | 曲目记录：u32 条数（最多 6），+0x530 起 `SONG TAG` × 6 格（每格 0x20），数据第 1 个字 = 歌曲 ID（0~15），第 2 个字是序号（新的大），第 3 个字未解 |
| +0xAB0 | 14 × i32 的 Unit 标量块（见下） |
| +0xB00 | 最后游玩时间：u16 年、月、星期、日、时、分、秒、毫秒 |

Unit 标量块（序列化函数 `0x82249D10`，括号里是 Unit 对象偏移）：

| 槽内偏移 | 内容 |
|---|---|
| +0xAC4 | 试镜标志（`+0x370`）：0x4000 = SUPER IDOL 合格（スーパーアイドル 的判定），0x1/0x2/0x4/0x8 = 春/夏/秋/GP 祭典试镜已不再出现；其余位对应别的试镜（`0x8223DCE0`） |
| +0xAD8 | 日历周（`+0x23C`） |
| +0xADC | 已过周数（`+0x240`） |
| +0xAE0 | 教程状态（`+0x244`） |

### 制作人块（0x11B40 起，序列化函数 `0x82235998`）

奖杯列表之后依次是：等级、`+0x40`、`+0x44`、Unit 数、`+0x8C` 等 15 个 i32（0x11C90 起），然后每段按 16 字节对齐：`+0x780`（0x14 字节，0x11CD0）、`+0x4C`（0xC，0x11CF0）、`+0x534`（400，0x11D00）、`+0x6C4`（0xA0，0x11E90）、`+0x794`（0x28，0x11F30）、`+0x7BC`（0x28，0x11F60）、偶像结局次数 `+0x60`（0x28，0x11F90），正好到 0x11FC0 的 Unit 槽。

偶像 ID → 下标的换算在 `0x8222E428`：1~8 → 0~7，9、10（亜美、真美）→ 8，11（美希）→ 9。

已验证：

- 槽是自包含的。把一个槽整块复制到空槽、改掉偶像 ID 和名字，再把 0x39D0D0 加一，游戏能列出来，也能正常推进和存档，游戏只会写回这个槽和几个累计值。
- 没有找到槽和槽外数据互相引用的地方；唯一需要配合改的是 0x39D0D0。
- 槽内的周数、等级等推进字段没有逐个解出来，目前做法是从游戏实际存过的存档里整槽搬运。
