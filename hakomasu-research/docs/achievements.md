# 成就（トロフィー）

## 存档里的奖杯

0x11B40 = 已获得数，0x11B50 起最多 10 条 `PTRP TAG`（每条 0x20 字节）。记录**按获得顺序**排列，每条数据的第一个字（记录 `+0x10`）才是奖杯 ID（`PTRP TAG` 类只有这一个字段，构造函数 `0x82239C20`）。以前写的"位置即奖杯 ID"是错的：一份只拿到 スーパーアイドル 和 ベストエンディング 的存档，两条记录的 ID 是 4、5。奖杯 ID：

| ID | 奖杯 | ID | 奖杯 |
|---|---|---|---|
| 1 | 10アイドル | 6 | A100 |
| 2 | 16ソング | 7 | C100 |
| 3 | 4シーズン | 8 | L100 |
| 4 | スーパーアイドル | 9 | M100 |
| 5 | ベストエンディング | 10 | 真アイドルマスター |

## 触发方式（Xenia Canary 上验证）

- 成就不是读档时按状态判定，而是在事件点发放：当天结束/夜间检查、结局、片尾字幕之后等。
- 把奖杯记录清空（0x11B40 = 0，0x11B50–0x11C8F 清零）后，游戏会在下一次满足条件的事件点重新发放，Xbox 成就跟着解锁。
- 用"S 级、离结局两周"的 Unit，再把制作人计数设成 99 来测：跳出了スーパーアイドル、A100、C100、L100、M100。
- ベストエンディング 要巨蛋演唱会成功；第一次失败过，重打成功后获得。
- 最终模拟器存档里 10 个全部获得。其中 10アイドル、16ソング、4シーズン、真アイドルマスター 的具体触发时机没有记录下来。

## 发放点（xex 反编译，基础版 0.0.0.1 地址）

以下来自对 `default.xex`（未打 TU）的反编译，没有在游戏里逐条复现。地址是基础版的，TU 版需要按 [week-cycle.md](week-cycle.md) 的方法换算。

### 发放机制

- 制作人对象（全局 `0x82812FE8`，vtable `0x820331B4`）的 vt `+0x68`（`0x82236420`）是"加奖杯"：把 `PTRP TAG`（`+0x10` = 奖杯 ID）加入制作人的奖杯列表，ID 在 1~10 时调用 `0x8219E9A0` 把成就排进队列。
- `0x8219E9A0` 用表 `0x82018FF0` 把奖杯 ID 换成 Xbox 成就 ID：奖杯 1~10 → 成就 8~17。
- vt `+0x70`（`0x822358D8`）是"已拥有该奖杯"，每个发放点都先查它，所以同一奖杯只发一次。
- 全部发放点只有两处：**夜间事务所（OfficeNight）** 和 **结局演唱会之后（ED_ConcertAfter）**。

### 夜间事务所：A100 / C100 / L100 / M100 / スーパーアイドル / 4シーズン

- 判定在 OfficeNight 的初始化 `0x822B1BF8`：读取制作人 PEVA 的副本，条件满足且还没有这个奖杯时，在场景 `+0x30C` 置位 `1 << 奖杯ID`。
- 发放在 OfficeNight 的结束步骤（Impl vt `+0x38`，`0x822B33B0` 的第一帧调用 `0x822B2ED0`）：按 `+0x30C` 的位逐个调用"加奖杯"。之后才是 vt `+0x3C` 退出，退出时调用 `System::EndOfWeek`。
- 所以判定用的是**上一次周结算之后的数据**。周结算（`EndOfWeek`）里才加的计数，要到下一周的夜间才会被看到。
- 休息周不经过夜间事务所（OffSchedule 退出时直接 `EndOfWeek`，见 [week-cycle.md](week-cycle.md)），那一周不做夜间判定，条件满足的成就顺延到下一个有夜间的周。

| 奖杯 | 判定（制作人 PEVA；下标见 [week-cycle.md](week-cycle.md) 第 3 节） | 计数在哪里增加 | 解锁时机 |
|---|---|---|---|
| 6 A100 | `+0x14`（下标 1，试镜合格次数）≥ 100 | `EndOfWeek` | 第 100 次合格那一周的**下一周**夜间 |
| 7 C100 | `+0x48` + `+0x4C`（下标 11、12，营业评价的前两档）≥ 100 | `EndOfWeek` | 同上 |
| 8 L100 | `+0x34` + `+0x38`（下标 15、16，课程评价的前两档）≥ 100 | `EndOfWeek` | 同上 |
| 9 M100 | `+0x58`（下标 20，累计获得的回忆数）≥ 100 | 偶像获得回忆时**立即**加（IDOL vt `+0x68` = `0x8222EF30`：增量 > 0 时同时加到 Unit PEVA 和制作人 PEVA 的 vt `+0xD4`，再把偶像 `+0x28` 夹在 0~99）。用掉回忆是负增量，不计入 | 获得第 100 个回忆的那一周夜间 |
| 4 スーパーアイドル | 当前 Unit 的 vt `+0x78(2)`：Unit `+0x370` 的 `0x4000` 位 | 试镜结算 `System+0xE0`（`0x8223DCE0`）：ID 0x21 的试镜**合格**时置位 | 合格那一周的夜间（试镜结束后直接进入 OfficeNight） |
| 3 4シーズン | PEVA `+0x60`（下标 19）低 8 位全部为 1（`0x822395B0`） | 见下 | 见下 |

注：`EndOfWeek` 按 TODAY `+0x1C` 的值 0/1/2/3 分别给下标 11/12/13/14 加 1（`0x82239028`/`40`/`58`/`70`），C100 看 0 和 1 两档。Xenia 实测：营业 Normal 记入下标 13、Perfect 记入下标 11（存档核对），C100 在 Perfect 之后第一个有夜间事务所的周发放；所以前两档是 Perfect 和 Good（Good 没有单独测）。L100 的课程评价档位没有在游戏里核对。

**4シーズン 的 8 个位**（`0x822395D0` 是 OR 置位，只有两处调用）：

| 位 | 来源 | 写入位置 |
|---|---|---|
| 0x01 / 0x04 / 0x10 / 0x40 | 试镜 ID 0x22 / 0x23 / 0x24 / 0x25 **合格** | 试镜结算 `0x8223DCE0`（`0x8223E0F0`） |
| 0x02 / 0x08 / 0x20 / 0x80 | TODAY `+0x2C` 为 0x60 / 0x61 / 0x62 / 0x63 的那一周（季节祭典的营业） | `EndOfWeek`（`0x822416F0`） |

审核表 `auditionlist.bxr` 的标题序号与代码里的试镜 ID 一致：33（0x21）= SUPER IDOL，34~37（0x22~0x25）= 春祭りアイドルスペシャル、サマーフェスティバル、秋の大感謝祭スペシャル、輝け！アイドルマスターグランプリ。

- 最后一个位来自祭典营业时，这个位在 `EndOfWeek` 才写入，所以是**下一周**夜间解锁，与攻略的"第 4 个营业祭典的翌週"一致。
- 最后一个位来自祭典试镜合格时，同一周的夜间就会解锁。
- PEVA 是制作人的，**跨 Unit 累计**；不要求同一个 Unit 完成 8 项。
- TODAY `+0x2C` 是本周营业选中的事件 ID。事件名表（`0x8226FCE8` 里按 ID×0x20 填写）中 0x60~0x63 = `fes01`~`fes04`，对应各偶像的 `xxx_fes0N_a/b` 脚本（在 FES_ConcertBefore/After 里播放）。
- 写入只在营业选择（PromotionChooser）的第 0x16 步：选中营业项目后用 TODAY vt `+0x5C` 写入事件，事件 ID 为 0x60~0x63 时把行动类型设成 3（フェス），否则设成 1。所以**必须在营业里选祭典那一项**，不选（这周做课程、试镜、休息）就不会置位。
- `EndOfWeek` 只看事件 ID，没有看祭典演唱会的结果，所以选了祭典之后演唱会成绩好坏都会置位（推测，演唱会场景里有没有把 `+0x2C` 改掉的分支没有逐条读）。攻略写的"不需要到 high""营业祭典本身可以サボる"，按代码理解应该是指演唱会的表现，不是指可以不选。
- `StartOfWeek` 不清 `+0x2C`（`0x82248630` 只重置 `+0x58`），上一次的事件 ID 会留到下一次营业覆盖为止。留下来的祭典 ID 只会重复置同一个位，不会多出别的季节的位。

### 结局演唱会之后：10アイドル / 16ソング / ベストエンディング / 真アイドルマスター

`ED_ConcertAfter` 场景（Impl 的 TypeDescriptor `0x824ADFD4`）：

1. 初始化 `0x8227AA08`：
   - 按 Unit 人数，对每位成员调用制作人 vt `+0x9C`（`0x822352E8`，制作人 `+0x60 + 4×偶像` 加 1，10 个偶像各一格），再调用 vt `+0xA0`（`+0x88` 加 1，Unit 总数）。
   - 计算演唱会结果，写进 TODAY `+0x40`（见下）。
   - 计算总评分和新的制作人等级（见下）。
2. 演出序列 `0x82279208` 的第 0x17 步调用 `System` vt `+0xEC`（`0x8223F018`），在这里发放 4 个奖杯：

| 奖杯 | 判定 |
|---|---|
| 2 16ソング | 先把这个 Unit 曲目记录（Unit vt `+0x58`，每条 0x1C 字节，ID 为 -1 的跳过）里的歌曲 ID 逐个 OR 进制作人 PEVA `+0x64`（下标 21，PEVA vt `+0xE8`）；再判定低 16 位全部为 1（vt `+0xE4`） |
| 5 ベストエンディング | TODAY `+0x40` == 0 |
| 10 真アイドルマスター | 更新后的制作人等级（`+0x48`，vt `+0x54`）== 9 |
| 1 10アイドル | 制作人 `+0x60`~`+0x84` 这 10 个计数都 > 0（vt `+0xA4`） |

**ベストエンディング**（TODAY `+0x40` 由 `0x8227AA08` 写入）：

- 场景 `+0x100` = 演唱会得分 > 79（得分来自 `0x822C82D0` 返回的对象 vt `+0x2C`）。
- 场景 `+0x94` = 演唱会类型（同一对象 vt `+0x20`），场景 `+0x8C` = UNIT_TAG `+0x68`（`0x8224BE78`）。
- 只有"得分 ≥ 80、类型为 5、`+0x8C` < 2"时写 0，其他情况都写 1~8。
- 推测：类型 5 是巨蛋，`+0x8C` 是 Unit 等级（0 = S，1 = A），这样就是攻略说的"A 以上在巨蛋成功"。这两项的含义是按条件形状推的，没有单独证实。

**真アイドルマスター**（新等级 = 旧等级 + 表 `0x824ADC30`[旧等级][分档]）：

- 总评分是 5 项小分之和（场景 `+0xA0`、`+0xA4`、`+0xA8`、`+0xAC`、`+0xB0`），按 5 分一档分成 0~15 档：<10 为 0 档，10~14 为 1 档，……，75~79 为 14 档，≥80 为 15 档。
- 表中旧等级 8 那一行只有 14、15 档是 +1，所以**等级 8 时总评分 ≥ 75 才能升到 9**，与攻略的"アイドルマスター で 75 点以上"一致。
- 另外：新等级大于 7 时，如果 10 个偶像的计数不是都 > 0，会被压回 7。也就是说没拿 10アイドル 的条件，就升不到 8 以上。
- 等级的写回在 `0x8223F018` 里（制作人 vt `+0x50`），用的是 TODAY 里存的变化量；从场景 `+0xF4` 到 TODAY 的那一步没有逐条核对。
- 等级存在 `gamedata` 0x11C90，10 个偶像计数在 0x11F90（见 [gamedata-format.md](gamedata-format.md)）。

升降表 `0x824ADC30`（行 = 旧等级，列 = 分档 0~15）：

| 旧等级 | 分档 → 变化 |
|---|---|
| 0 | 0~9 → +1，10~15 → +2 |
| 1 | 0~2 → 0，3~9 → +1，10~15 → +2 |
| 2 | 0~3 → 0，4~9 → +1，10~15 → +2 |
| 3 | 0~4 → 0，5~12 → +1，13~15 → +2 |
| 4 | 0~5 → 0，6~12 → +1，13~15 → +2 |
| 5 | 0~4 → −1，5~6 → 0，7~12 → +1，13~15 → +2 |
| 6 | 0~7 → −1，8~9 → 0，10~12 → +1，13~15 → +2 |
| 7 | 0~7 → −1，8~12 → 0，13~15 → +1 |
| 8 | 0~7 → −2，8~13 → 0，14~15 → +1 |
| 9 | 0~7 → −2，8~15 → 0 |

由此：等级 7 时一次结局最多到 8，所以等级 ≤ 7 的存档不可能在一次结局里拿到 真アイドルマスター；等级 8 或 9 时，10 个计数不全的结局会被压回 7。

### 季节祭典试镜什么时候出现

试镜栏位刷新函数 `0x8230C410` 的 e 类（case 4）第 1 个栏位：按 Unit 日历周（`+0x23C`）判断，并且 Unit 试镜标志（`+0x370`，存档槽内 +0xAC4）里对应的位没有置上：

| 日历周 | 试镜 | 标志位 | 4シーズン 位 |
|---|---|---|---|
| 8~11 | e2 春祭りアイドルスペシャル（0x22） | 0x1 | 0x01 |
| 21~24 | e3 サマーフェスティバル（0x23） | 0x2 | 0x04 |
| 34~37 | e4 秋の大感謝祭スペシャル（0x24） | 0x4 | 0x10 |
| 47~50 | e5 輝け！アイドルマスターグランプリ（0x25） | 0x8 | 0x40 |
| 其他 | e1 SUPER IDOL（0x21） | | |

e1~e5 在 `auditionlist.bxr` 里的记录顺序是 33~37，`week` 字段都是 1~52，季节限制只在代码里。

### 与攻略对照

| 奖杯 | 攻略 | 反编译 |
|---|---|---|
| 10アイドル | 第 10 人所在 Unit 引退时 | 一致（结局演唱会之后） |
| 16ソング | 第 16 首歌所在 Unit 引退时 | 一致；按引退 Unit 的曲目记录计入 |
| 4シーズン | 第 4 个营业祭典的翌週 | 最后一项是营业时一致；最后一项是试镜时当周夜间就解锁 |
| スーパーアイドル | 当周夜间 | 一致 |
| ベストエンディング | Best End 引退时 | 一致 |
| A100 / C100 / L100 | 达成的翌週夜间 | 一致 |
| M100 | 达成的翌週夜间 | 计数在获得回忆时立即增加，**当周夜间**解锁（Xenia 实测：营业 Communication 评价 Normal 也给了 1 个回忆，当晚解锁） |
| 真アイドルマスター | 升格为真アイマス时 | 一致（等级 8、总评分 ≥ 75，并且要满足 10アイドル 的条件） |
